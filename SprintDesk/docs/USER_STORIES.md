# User stories — SprintDesk

## Роли и права

| Роль | Возможности |
| --- | --- |
| Гость | Регистрация, вход |
| Участник (`member`) | Просмотр, создание, редактирование и удаление только своих задач |
| Администратор (`admin`) | Просмотр всех задач, управление любыми задачами, назначение исполнителя, просмотр списка участников |

Администратор создаётся командой `python -m scripts.seed_admin` с переменными `ADMIN_EMAIL` и `ADMIN_PASSWORD`. Через публичную регистрацию нельзя получить права администратора.

## Пользовательские истории

**US-01 — Регистрация.** Как гость, я хочу зарегистрироваться по имени, email и паролю, чтобы получить личное пространство задач.

Критерии приёмки: имя от 2 символов; корректный email; пароль от 8 символов; email уникален; новый пользователь получает роль `member`.

**US-02 — Вход.** Как участник, я хочу войти с email и паролем, чтобы видеть свои задачи.

Критерии приёмки: корректные данные возвращают токен; неверные — 401; защищённые API требуют токен.

**US-03 — Создание задач.** Как участник, я хочу добавить задачу с названием, описанием и приоритетом, чтобы планировать работу.

Критерии приёмки: название 2–120 символов; приоритет 1–3; сохраняется владелец; запись присутствует в БД.

**US-04 — Доска.** Как участник, я хочу видеть задачи по статусам «К выполнению», «В процессе», «Готово», чтобы контролировать прогресс.

Критерии приёмки: доступны три колонки; показана статистика; можно фильтровать по названию и приоритету.

**US-05 — Обновление.** Как участник, я хочу менять описание, статус и приоритет своей задачи, чтобы поддерживать план актуальным.

Критерии приёмки: обновления сохраняются в БД; к чужой задаче доступа нет.

**US-06 — Удаление.** Как участник, я хочу удалять свои задачи, чтобы не хранить неактуальные записи.

Критерии приёмки: запись удалена из БД; чужая задача недоступна.

**US-07 — Управление командой.** Как администратор, я хочу назначать задачи участникам, чтобы распределять работу.

Критерии приёмки: администратор видит участников и все задачи; может сменить владельца; обычный участник не может назначать задачи другим.

## Модель данных

**users:** `id` PK; `name` VARCHAR(80) NOT NULL; `email` VARCHAR(254) UNIQUE NOT NULL; `password_hash` VARCHAR(256) NOT NULL; `role` enum-like CHECK (`admin`, `member`); `created_at` TIMESTAMP.

**tasks:** `id` PK; `title` VARCHAR(120) NOT NULL; `description` TEXT NOT NULL; `status` CHECK (`todo`, `in_progress`, `done`); `priority` CHECK (1..3); `owner_id` FK → `users.id`; `created_at`, `updated_at` TIMESTAMP.

Связь: один пользователь → множество задач. При удалении пользователя связанные задачи удаляются каскадно.

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| POST | `/api/auth/register` | Регистрация |
| POST | `/api/auth/login` | Авторизация |
| GET | `/api/auth/me` | Текущий участник |
| GET | `/api/tasks` | Список доступных задач |
| POST | `/api/tasks` | Создание задачи |
| GET | `/api/tasks/{id}` | Детали задачи |
| PATCH | `/api/tasks/{id}` | Изменение задачи |
| DELETE | `/api/tasks/{id}` | Удаление задачи |
| GET | `/api/users` | Участники, только администратор |
| GET | `/api/health` | Проверка сервиса |

Документация OpenAPI: `/api/docs`.
